# Publish Agent

## Purpose

Last node in the LangGraph pipeline (`backend/pipeline/graph.py`). Receives
approved `ContentVariant[]` from `review_gate`, formats each variant into a
channel-styled HTML email, and dispatches it via SMTP to a preconfigured
recipient list.

**Demo mode contract:** All channels (`linkedin`, `email`, `sms`,
`social_post`, `display_ad`, `push_notification`) are delivered as email
regardless of their target channel. Each email is visually styled to simulate
how that content would appear on its real platform — so a tester opening
MailHog sees a LinkedIn-styled card, an SMS bubble, or an ad unit, all inside
a well-designed HTML email shell. This removes the need for real platform API
credentials while making the demo output genuinely impressive.

## Write permissions (`backend/pipeline/agents/base.py::AGENT_WRITE_PERMISSIONS["publishing_agent"]`)

```
publication_receipts, variants, current_phase, errors
```

## Inputs consumed from state

| Field | Usage |
|---|---|
| `variants` | Each variant's `final_content` → `personalized_content` → `generated_content` (first non-None wins) |
| `brief` | `objective` (email subject), `channels`, `locales`, `target_audience` |
| `aggregated_scores` | Composite score + criterion breakdown rendered in email footer |
| `campaign_id`, `brand_id`, `org_id` | Metadata included in email header |

Only variants with `status` in `{"approved", "generated"}` are published.
Variants with `status == "rejected"` are silently skipped (no receipt written).

## SMTP configuration

MailHog is already declared in `docker-compose.yml` (ports `1025` SMTP,
`8025` web UI). No new infrastructure is needed.

Three new fields in `backend/core/config.py`:

```python
PUBLISH_SMTP_HOST: str = "mailhog"          # "localhost" when running outside Docker
PUBLISH_SMTP_PORT: int = 1025               # MailHog default; no auth, no TLS
PUBLISH_RECIPIENT_EMAILS: str = ""          # comma-separated: "demo@acme.com,qa@acme.com"
```

The `worker` service in `docker-compose.yml` exposes these as environment
variables (`PUBLISH_SMTP_HOST=mailhog`). When running the worker directly on
the host, set `PUBLISH_SMTP_HOST=localhost`.

`aiosmtplib` is used for all sends — fully async, no thread-blocking. No
authentication or TLS is configured because MailHog accepts all mail
anonymously.

If `PUBLISH_RECIPIENT_EMAILS` is empty the agent logs a warning and returns
a `current_phase="published"` with empty receipts. This keeps smoke tests and
CI green without requiring any email configuration.

### Per-channel content blocks

| Channel | Visual treatment |
|---|---|
| `email` | Clean card, blue CTA button (`#2563eb`), professional layout, subject-line heading |
| `linkedin` | LinkedIn blue (`#0077b5`) accent bar, profile-card layout, "LinkedIn Post" chip, character-count badge |
| `sms` | iMessage-style speech bubble (green `#34c759`), monospace short text, "SMS · 160 chars max" label |
| `social_post` | Instagram-gradient top border, hashtag styling in purple, emoji rendering area |
| `display_ad` | Bordered box with "AD" watermark, headline/body/CTA three-zone layout |
| `push_notification` | Mobile notification card, app icon placeholder, 1-line title + short body |
| *(any other)* | Generic card with channel name badge |

All templates are fully inline-styled (no external CSS) for maximum email
client compatibility. The outer wrapper uses a soft gradient background
(`#f0f4ff`), white content card, and 600 px max-width.

## Steps

1. **Read recipients**
   - Split `settings.PUBLISH_RECIPIENT_EMAILS` on commas, strip whitespace.
   - If the resulting list is empty, log `publish_skipped_no_recipients` and
     return early with `publication_receipts=[]`, `current_phase="published"`.

2. **Filter variants**
   - Collect variants where `status in {"approved", "generated"}`.
   - If none qualify, log `publish_no_eligible_variants` and return early.

3. **For each eligible variant**

   a. Resolve content: `final_content` → `personalized_content` →
      `generated_content` (first non-`None` non-empty string).

   b. Look up `AggregatedScore` for this variant from `state["aggregated_scores"]`
      (match on `variant_id == task_id`). Pass `None` if not found — the
      template degrades gracefully.

   c. Call `build_campaign_email_html(variant, brief, score)` from
      `pipeline/agents/email_templates.py` to produce the full HTML string.

   d. Build a `MIMEMultipart("alternative")` message:
      - `From`: `OmniBrand Studio <omnibrand-demo@localhost>`
      - `To`: comma-joined recipient list
      - `Subject`: `[OmniBrand Demo] {channel.upper()} | {objective[:60]} — {locale}`
      - `Message-ID`: `<{uuid4()}@omnibrand-demo>`
      - Attach both a plain-text fallback and the HTML part.

   e. Send via `aiosmtplib.send(msg, hostname=..., port=...)` — wrapped in
      its own `try/except` so one failed send does not abort remaining variants.

   f. Build `PublicationReceipt`:
      ```python
      {
          "variant_id": variant["task_id"],
          "channel": variant["channel"],
          "locale": variant["locale"],
          "platform_publication_id": message_id,
          "public_url": None,
          "adapter_used": "smtp_demo",
          "publish_status": "sent",   # or "failed"
          "published_at": datetime.now(UTC).isoformat(),
          "error_message": None,      # or str(exc) on failure
      }
      ```

   g. Update `variant["status"] = "published"` on success (or `"publish_failed"`
      on error). Update `variant["final_content"]` with the resolved content
      string if it was previously `None`.

4. **Set phase**
   - `current_phase = "published"` unconditionally (even if some variants
     failed — the agent ran to completion).

5. **Return partial state**
   ```python
   return {
       "publication_receipts": receipts,
       "variants": updated_variants,
       "current_phase": "published",
       "errors": error_strings,   # only if sends failed
   }
   ```

## Failure handling

- **Per-variant isolation** — each variant's send is wrapped independently.
  A single bad MIME encoding or transient SMTP error writes
  `publish_status="failed"` + `error_message` to that variant's receipt and
  continues to the next variant.
- **SMTP unreachable** — if the `aiosmtplib` connection itself fails (e.g.
  MailHog not running), the outer `safe_agent_run` wrapper catches the
  exception, appends to `errors`, and returns a minimal dict so the pipeline
  reaches `current_phase="published"` rather than crashing LangGraph.
- **No retry logic** — demo scope only. Production adapters would add
  exponential backoff.

## Resume-after-interrupt path

The graph is compiled with `interrupt_before_review_gate=False` in demo mode
(default changed from `True`). This means `graph.ainvoke()` runs straight
through `review_gate → publishing_agent → END` without pausing.

For production use, set `interrupt_before_review_gate=True` and add a
`POST /campaigns/{id}/review` endpoint that calls:
```python
await graph.ainvoke(None, config={"configurable": {"thread_id": campaign_id}})
```
The `None` input tells LangGraph to resume from the saved checkpoint — the
publish agent will then execute with the review decision already in state.

            r.strip()
            for r in settings.PUBLISH_RECIPIENT_EMAILS.split(",")

            # resolve content, build HTML, send SMTP, build receipt ...
            ...

        return {
            "publication_receipts": receipts,
            "variants": updated_variants,
            "current_phase": "published",
            **({"errors": errors} if errors else {}),
        }
    return await safe_agent_run(_impl, state)
